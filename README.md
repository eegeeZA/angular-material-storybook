# Angular + Material + Storybook

[![CI](https://github.com/eegeeZA/angular-material-storybook/actions/workflows/ci.yml/badge.svg)](https://github.com/eegeeZA/angular-material-storybook/actions/workflows/ci.yml)

An example of how [Angular](https://angular.dev/),
[Angular Material](https://material.angular.dev/) and
[Storybook](https://storybook.js.org/) fit together.

| Tool                | Version |
| ------------------- | ------- |
| Angular CLI         | 22.2    |
| Angular Material    | 22.2    |
| Storybook (Angular) | 10.6    |
| TypeScript          | 6.0     |
| Node.js             | 24 LTS  |

## Getting started

```sh
npm ci
```

## Storybook

Run `npm run storybook` and open `http://localhost:6006/`. The stories live in
`src/stories/`:

- **Material/Button** - the Material 3 button appearances, icon buttons and
  FABs, with a playground story driven by controls.
- **Material/ButtonToggle** - a button toggle group whose change events show in
  the actions panel.
- **Example/Button** - the example component generated by Storybook.

`npm run build-storybook` builds the static Storybook into `storybook-static/`.
Every push to `master` that passes CI deploys that build to GitHub Pages:
<https://eegeeza.github.io/angular-material-storybook/>.

## Development server

Run `npm start` and open `http://localhost:4200/`. The app reloads when a
source file changes. `npm run build` makes a production build, which
inlines Google Fonts and so needs network access.

## Tests

- `npm test` runs the unit tests with [Vitest](https://vitest.dev/).
- `npm run test-storybook` renders every story as a test in headless
  Chromium, with its play function and accessibility checks (run
  `npx playwright install chromium` once first).

## Lint and format

- `npm run lint` checks the code with ESLint (angular-eslint and the
  Storybook plugin); `npm run lint:fix` fixes what it can.
- `npm run format:check` checks the formatting with Prettier;
  `npm run format` rewrites the files.

## CI

[`.github/workflows/ci.yml`](.github/workflows/ci.yml) runs on every pull
request and on pushes to `master`: lint, format check, production build,
unit tests, story tests and the static Storybook build. It uses only the
read-only scripts.

On a push to `master`, a second job deploys the static Storybook that the
first job built to GitHub Pages. Pull requests never deploy.

`node scripts/check-site.mts` checks the deployed site: it opens every story
and docs page in headless Chromium and fails on a failed request, an HTTP
error, a story that does not render, a filled button without the theme colour
or an icon without the Material Symbols font. Pass a URL to check a
`storybook-static` served elsewhere.
